# RecPlanet on WordPress: the plan

Written 20 September 2026 from the live-site audit and the database sample. Companion documents: `migration/findings-2026-09-20.md` (what the data holds) and the approved visual direction at https://claude.ai/artifact/PrvwWn555ESYLCUAeH6AJk.

## 1. What we are building

One custom WordPress theme plus one companion plugin, hosted on WordPress.com Business, replacing a Drupal 6 site that holds 67,435 hand-made park records, a photo contest, and a blog. (Confirmed 21 September 2026 after considering theme-only.)

The plugin holds the data model (parks, photos, contests, the counter, the search index, the importer) so it survives a theme change. The theme holds the look and the templates.

Principles that decide the hard calls:

- **The record is the product.** Every park page must look complete with the data most records have: a name, a place, an acreage, three activities and a paragraph. Only 741 parks have a picture and 2,406 a website, so those are bonuses, never the layout's spine.
- **Keep every URL that ranks.** 66,320 parks live at `/{state}/{city}/{slug}` and stay there.
- **Editorial-only parks.** Members vote, upload photos and enter contests. Nobody but editors adds or edits parks.
- **The counter is a sum, not a number.** It is always recomputed from published parks, never typed in.

Taxonomies on `park`:

| Taxonomy | Shape | Source | Count |
|---|---|---|---|
| `activity` | flat | field_pactivities, fixed list | 45 terms |
| `facility` | flat | parsed from Park Tags | ~80 terms after merging variants |

### Custom tables (companion plugin)

| Table | Purpose |
|---|---|
| `rp_park_index` | one row per published park: post_id, lat, lon, POINT with SPATIAL index, acreage, country, state, county, city, activity bits, facility bits. Every map, near-me and roll-up query hits this, never postmeta. |
| `rp_acre_rollup` | scope (world, country, state, county, city, steward), scope_id, park_count, acres. Recomputed for the affected scopes whenever a park is published, unpublished, deleted or its acreage or place changes. |
| `rp_acre_ledger` | the public feed: post_id, delta_acres, event (added, corrected, removed), created_at. |
| `rp_votes` | photo_id, user_id, value, created_at, unique on (photo_id, user_id). |
| `rp_freshness` | park_id, user_id or IP hash, answer (yes/no), note, created_at. |
| `rp_redirects` | old_path → new_path, hit count. Generated by the importer. |

## 3. The acre counter

**Definition.** `SUM(acreage)` over published parks, read from `rp_acre_rollup` where scope = world. Never a stored constant.

**Keeping it current.** On every park save, publish, unpublish, delete or trash, the plugin recomputes the roll-ups for that park's world, country, state, county, city and steward scopes and appends a ledger row. A nightly job re-sums everything from scratch and logs any drift, so a missed hook can never leave the number wrong for more than a day.

**What the visitor sees.**

| Layer | Content |
|---|---|
| Headline number | World total, 4,744,108,374.74 acres, as on the old site. Moves when any park is added. |
| Second line | United States, 828,975,859.79 acres, and the rest of the world, with Antarctica's 3.46 billion named so the headline stays honest. |
| Ledger | the last twenty ledger rows: "+22.43 acres, Towne Lake Park, Irving TX, today". |
| Growth chart | acres over time from the park publish dates; 2010 import, the quiet decade, the 2020 to 2026 surge. |
| Acre ribbon | on every park, city, county, state and country page: world > country > state > county > city > this place, from the roll-up table. |

Decided 21 September 2026: the world total stays the headline, as on the old site.

**Embeddable counter.** A REST endpoint `/wp-json/recplanet/v1/counter` returns the roll-ups as JSON with a five-minute cache. A one-line script tag renders the counter on any other site and links back.

### Sitemaps

67,000 parks plus tens of thousands of place and facility pages need a sitemap index; WordPress core caps each sitemap file at 2,000 URLs and handles the index. Today only 5,178 URLs are in the sitemap. This alone should be the largest search-traffic change of the project.

## 5. Members, photos and the contest

**Roles.** Administrator and Editor manage parks, contests and moderation. A custom `member` role can upload photos, vote, comment, and see their own dashboard. Members cannot create or edit parks. Registration asks for email confirmation; WordPress.com's Akismet plus a honeypot handles the spam that filled the old user table.

**Photo upload.** A front-end form: pick the image, pick the park (search as you type, with the nearest park suggested from the photo's EXIF location), caption, optional contest entry, a checkbox confirming the contributor holds the rights. The photo lands in "pending"; an editor approves from the normal WordPress list. Approved photos appear on the park page and in the contributor's gallery.

**Contest flow.** An editor creates a contest with dates and prizes. While open, members enter photos. When voting opens, any signed-in member can give each photo one vote; a member can change or withdraw their vote until voting closes. When closed, the editor confirms winners, the results page is published, and the winning photo becomes the home page hero for the following week with the photographer credited.

Decided 21 September 2026: as on the old site, visitors can vote without an account. Abuse control is one vote per photo per browser plus IP rate limiting; signed-in members' votes are tied to the account and can be changed until voting closes.

**Migration of the old contest.** 254 photos, their 16,084 votes summarised into a count and score per photo, contributor display names kept, all in one archived contest so the historical results stay visible.

## 8. Search and maps on WordPress.com

- **Maps** (revised 21 September 2026, free-only): two free-without-limit services. **Google Maps Embed API** for anything that is one place: the map with a pin on every park page, Street View on every park page, and a Google Maps link for directions. The key is restricted to the Embed API alone so it can never bill. **MapLibre GL JS with OpenFreeMap vector tiles** (no key, no limit) for everything that shows our own data: the atlas, clusters that count acres, the activity lens, select-an-area, the year scrubber, city and state maps. The base map is styled in the brand colours through the style file. Fallback if OpenFreeMap changes terms: Protomaps PMTiles hosted by us, a one-afternoon switch. No Places, Routes, Distance Matrix, Elevation or 3D Tiles: search is ours, travel time is a straight-line estimate, and Google's opening hours, photos, routed minutes and the flyover are out of scope. Bad coordinates are fixed once, editorially, with Nominatim at its one-request-per-second policy.
- **Near me**: browser geolocation, then a radius query on the spatial index, results ordered by distance, walking-time estimate from straight-line distance.
- **Search box**: park titles, place names and activity names from a small dedicated table with a FULLTEXT index; no external service.
- **Caching**: WordPress.com's page cache and CDN in front; the plugin caches roll-ups and API responses in the object cache with invalidation on park save.


### The atlas: map features (added 21 September 2026)

Demonstrated on real Texas data in the prototype (https://claude.ai/artifact/944CiAnYd9ZRUAkXNRfGEv, Atlas page):

- **Clusters that count acres.** Zoomed out, each cluster shows the number of places and the acres they hold. Click to open it.
- **Four views of the same data.** Places; acres, where dot size is acreage; managed by, coloured city / county / state / federal; density heat.
- **Activity lens.** Pick one activity and everything else fades; the in-view counts follow.
- **Put me here.** Tap the map to place yourself; rings show 15 minutes on foot, by bike or 30 by car; the list orders places by travel time.
- **Select an area.** Draw a box and get a counter for it: places, acres, what you can do there, who manages it, largest first. A counter for any neighbourhood.
- **Watch it grow.** A year scrubber from 2010 to 2026 with a play button; the map fills in as the records were added.
- **Contribute mode.** Show only places with no photo yet, so contest entries go where they fill a gap.
- **In-view counter** always shows places and acres for whatever is on screen with the current filters.
- **Live site**: the atlas on MapLibre with OpenFreeMap tiles in the brand colours, viewport-bounded data requests to our own endpoint, a shareable URL for any view; Google Embed for the single-park map and Street View. Routed minutes, Google Places details and the 3D flyover are out of scope under the free-only decision.

### The home page side companion (added 21 September 2026)

## 9. Migration

### What to export from Drupal, and how

Table exports only, no joins. In phpMyAdmin: select the database, Export, Custom, tick these tables, SQL format, Go. Under 250 MB total.

`node`, `node_revisions`, `content_type_world_parks`, `content_field_pactivities`, `content_field_parkimage`, `content_type_photo_contest`, `content_type_upload_park_picture`, `content_field_park_picture`, `content_type_blogs`, `content_field_blog_image`, `content_field_node_image`, `location`, `location_instance`, `url_alias`, `term_data`, `term_hierarchy`, `term_node`, `vocabulary`, `content_node_field`, `content_node_field_instance`, `files`, `votingapi_vote`, `comments`, `nodewords`, `users` (only uid and name are used, for photo credits).

Plus the files folder `sites/default/files` over FTP, about 1.7 GB, mostly contest and park photos.

Skip everything else, in particular `watchdog`, `boost_cache`, `captcha_sessions`, `spam_*`, `sessions`, `cache_*`, `search_*`, `location_old`, `parks`, `migrate_*`.

### The importer

A WP-CLI command in the companion plugin, run over SSH on WordPress.com, reading the exported SQL loaded into a scratch database or parsed directly.

- Keyed on `legacy_nid`, so running it twice updates rather than duplicates.
- `--since=<timestamp>` re-imports only nodes changed after that time, for delta syncs during the build.
- Cleans HTML: strips `style`, `class`, `font`, `span` wrappers and Word artefacts; keeps paragraphs, links, lists, emphasis.
- Normalises ownership into steward level and name by pattern; unmatched values go to level "other" with a report.
- Backfills activities for the 16,124 parks that have none, from Park Tags (about 4,000, mostly Hunting on wildlife areas) and from the description text (about 800), as suggestions held in a review queue that the editor approves in bulk (decided 21 September 2026).
- Parses each Park Tag into place and facility; unparseable tags go to a report, not to the site.
- Takes the first location row when a park has two.
- Flags the 42 duplicate pairs, the 8 zero-coordinate parks, the 111 stateless US parks and the 989 acreage-less parks in a report for editorial review after import.
- Writes every old path into `rp_redirects`.
- Rebuilds `rp_park_index` and the roll-ups at the end.

### Cutover

1. Full import into the new site while it is still private. Review the reports, fix data, iterate on the importer.
2. Build and test the theme against real data.
3. Weekly delta imports so new parks keep flowing across.
4. Launch week: final delta, a one-day content freeze on the old site, DNS to WordPress.com, redirects live, sitemaps submitted, old site kept read-only for a month as a fallback.
